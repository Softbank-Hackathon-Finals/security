## 변경 이유와 범위

기존 Sova 화면을 유지하면서 구성 요소별 경고·의존성을 표시할 읽기 전용 투영이 필요했다.
기존 `SecuritySnapshot`, 그래프, 통제 판정을 재사용하고 새 탐지기·판정기·실행기를 만들지 않았다.

- 테넌트·앱·환경 쌍·자원 revision을 현재 계획에 결속한다.
- 48개 자원·96개 관계 이내로 제한한다. 원문 자원명·경로 대신 범위에 결속된 불투명 ID를 쓴다.
- 구성 위반만 경고로 표시한다. 실행 상태·트래픽·격리·전환·복구는 미확인으로 남긴다.
- 기존 그래프 유효기간을 보존한다. 저장된 그래프나 로컬 시험을 실제 수집으로 승격하지 않는다.
- 호스트의 생산자 인증과 기존 T10 권한 확인은 별도 필수 조건이다.

연결 방식은 [표시 투영 계약](../console-workload-projection.md)에 정리했다.

## 플랫폼 읽기 전용 관측

2026-11-07 05:25 KST에 `bravo-personal`과 기존 플랫폼 SSM 경로로 재조회했다.
계정·클러스터 신원을 대조했고, 이번 조회의 배포 세대는 전후 동일했다.

- Reader·등록 API·관측 수신기: Ready 1/1.
- 워크플로 호스트: Ready 0/1, CrashLoopBackOff. 현재 프로세스의 성공 경로를 인수할 수 없다.
- Reader와 호스트/등록 이미지 digest는 이전 04:18 관측과 같고, 원본 소스는 위 표의 `445848d`다.
- 세 설정 객체의 UID·resourceVersion은 이전 관측과 같았다. 두 수집기의 해시 방식이
  전체 문서와 항목별 해시로 다르므로 이를 직접 비교해 설정 변경이라고 판단하지 않았다.
- 제가 연 SSM 세션을 종료했다. exec·배포·patch·restart·권한 변경은 수행하지 않았다.

이는 해당 시각의 상태다. 이후 배포 성공이나 실패 원인 해소를 대신하지 않는다.

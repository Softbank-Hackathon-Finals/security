# ADR-0021: 플랫폼 정본을 소비하는 오프라인 인수 목록

- 상태: 개인 환경 채택, platform 제품 계약 변경 없음
- 날짜: 2026-11-07
- 기준: platform `c364e6284d2e635ff86001e2feac88560ed23ebc`

## 문제

TLS의 제한된 3 PASS를 20개 full 시험 전체의 충족으로 해석하거나, 수집기 코드·OK
heartbeat를 실제 양성 탐지 인수와 혼동할 수 있다. 기존 맥 인계 문서는 있지만 남은
시험과 제출 원문의 상태를 같은 형식으로 정리하는 도구가 없었다. 최신 T33 schema도
기존 개인 bridge의 고정본과 달랐다.

## 결정

1. T5 profiles·schema는 원본 바이트 hash로 고정해 소비한다. 시험 정의와 게이트를 새로
   만들지 않는다. 출발지·목적지의 full 필수 행은 입력이 없어도 모두 출력한다.
2. 개인 도구는 원문을 인증하지 않는 오프라인 진단이다. reported verdict와 수집 상태,
   만료/누락을 정리하되 실제 인수 상태와 실행 권한을 주지 않는다. T19가 최종 소비한다.
3. T33의 구형·최신 계약은 등록 digest로 선택한다. 최신 필드가 없는 Finding을
   최신이라고 추정하지 않으며 손실된 표시 식별자를 소유권 등록에 허용하지 않는다.
4. Sova CLI는 기존 소유자 제한 파일 reader를 재사용한다. 새로운 cloud login·수집
   daemon·writer·kubeconfig 실행기를 만들지 않는다.

## 결과와 제한

정본의 시험 추가·방법 변경은 hash 불일치로 드러나며 명시적 계약 검토가 필요하다.
20개 full 시험과 보안 문서의 22개 추가 검사는 별도 계약으로 유지한다. 현재 도구의
무입력 생성 성공이나 합성 3 PASS는 실환경 인수가 아니다. AWS/GCP의 원본 계정·자원과
마스킹 결과 사이의 인증된 mapping, 운영 수집, 감사·복원은 후속으로 남는다.

# ADR-0015: 부분 기록이 남은 로컬 감사 파일의 신규 판정 보류

- 상태: 구현·장애 주입 시험. 운영 T24 인수는 별도.
- 요구: SEC-PATCH-10, POL-10, SG-2, CTRL-07, `audit-trail` / `resource-budget`.
- 플랫폼 기준: `a610bbfb60d3a633597d75dc6e070addd3c3b559`. wire/API 변경 없음.

## 문제와 선택

2026-11-06 로컬 검증 중 저장 공간 장애를 겪어 감사 파일의 부분 쓰기도 조사했다.
기존 구현은 `os.write`가 일부 바이트를 쓴 뒤 ENOSPC를 반환하면 해당 요청을 거부했지만,
다음 요청은 미완성 JSON 뒤에 새 이벤트를 붙이고 성공할 수 있었다. 재현 시험이 변경 전 실패했다.

같은 열린 파일 descriptor에서 마지막 바이트가 줄바꿈인지 확인하고, 미완성 기록이면 추가 쓰기를
거부한다. 크기·권한·일반 파일·symlink 제한과 fsync 조건은 유지한다. 정상 상태의 추가 읽기는
1 byte이며 파일 크기에 비례한 재파싱이나 전체 로그 캐시는 없다.

파일을 자동 절단·삭제·덮어쓰기하거나 손상된 이벤트를 성공으로 복원하지 않는다. 운영자는
기존 파일을 조사/보존하고 T24 수집 상태를 확인한 다음 별도의 보호된 경로로 전환할 수 있다.
계속 실패하는 감사 기록 때문에 신규 판정을 보류하되 기존 앱 서비스의 트래픽은 별도다.

## 검증과 한계

격리된 임시 파일에서 한 번 정상 기록한 뒤 다음 쓰기 10 bytes만 실제 기록하고 ENOSPC를
주입한다. 이후 새 `LocalReviewAudit` 인스턴스도 거부하며 원본 bytes가 그대로 남는지 확인한다.
명시적으로 새 경로를 선택했을 때만 정상 기록을 재개한다. 실제 디스크를 소진시키는 시험은 아니다.

줄바꿈 검사는 부분 쓰기의 흔적을 감지하는 제한된 복구 조건이다. 모든 기존 JSON의 의미나
변조 방지·완전한 크래시 일관성·디렉터리 항목의 영속성·T24 보존을 증명하지 않는다.
같은 서비스 UID/관리자가 파일을 수정할 수 있는 위협은 보호된 디렉터리와 독립 T24로 처리해야 한다.
단일 프로세스/파일 전제는 유지하며 여러 프로세스의 공유 로그를 허용하는 변경이 아니다.

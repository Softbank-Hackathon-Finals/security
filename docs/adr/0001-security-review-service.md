# ADR-0001: 제한된 보안 판정 서비스와 기존 플랫폼 집행

- 상태: 채택 — 개인 환경 구현 기준. 플랫폼 운영 배포 인수는 별도.
- 날짜: 2026-11-06
- 기준 플랫폼: `f602b39a949b99f3e2e7be901103063e78a52a70`
- 요구사항: SEC-PATCH-01~10, CTRL-01~09, POL-01~12, SG-1~3

## 문제

0.10.0은 검증 로직과 Sova 실행 전후 검사를 제공하지만 호출 프로세스와 같은
신뢰 경계를 가진다. 독립 서비스의 인증·현재 등록·응답 결속·장애 처리를 검증해야 한다.
HTTP로 옮기는 것만으로 운영 실행 우회를 막거나 분산 원자성을 얻을 수는 없다.

## 결정

1. `sova-security`를 공통 검증 정본으로 유지한다. 선택형 서비스 인터페이스와
   제한된 HTTPS 소비자를 추가한다. 서비스는 배포·컷오버·승인·자격 발급을 하지 않는다.
2. 런타임 API는 등록된 검사 context의 판정만 제공한다. 호출자는 context 지문과
   요청 nonce를 보내며 정책, 증거, actor, 승인 또는 결과를 제출하지 않는다.
   정책·증거·신뢰 등록은 별도 인가된 관리 경로가 담당한다. 기본 허용 등록 API는 없다.
3. 호출 신원은 매 요청 현재 인증으로 확인하고 tenant/환경/action 권한을 검사한다.
   Kubernetes TokenReview 어댑터는 고정 audience 및 등록 ServiceAccount UID에 결속한다.
   플랫폼 T7의 발급 경로가 해당 audience를 지원하도록 인수한 뒤 연결한다. 기존 다른
   audience의 토큰을 보안 서비스 토큰으로 간주하지 않으며 새 발급기는 만들지 않는다.
4. 결과는 정확한 등록 context·원본 program·요청 nonce·호출자에 결속한다.
   짧은 응답 유효기간은 증거·등록·신원 중 가장 이른 만료를 넘지 않는다. 소비자는 TLS,
   현재 호스트 등록, 응답 결속과 시각을 검사한다. 판정은 단독 실행권이 아니다.
5. T10 계획/승인/단일 접수, T19 기존 통제·데이터 판정, T31/T12 실행, T24 감사 책임을
   유지한다. 현재 권한·철회·hold·계획 revision을 실행 접수와 실제 실행 경계에서 재검사한다.
   원격 판정 뒤 상태 변화 가능성은 남으므로 플랫폼 계획 잠금/epoch/fencing에 연결해야 한다.
6. 기존 앱 서비스의 가용성과 신규 변경 승인을 구분한다. 판정 실패·불명·만료는 신규 위험
   변경을 보류한다. 이미 적용된 효과는 기존 원장을 재조회하며 응답 유실로 재적용하지 않는다.
7. 먼저 읽기 전용 병행 비교를 제공한다. 병행 결과는 권한이나 승인으로 사용할 수 없다.
   강제 연결은 기존 승인·효과 검사를 보존하는 명시적 조합으로 제공한다.

## 플랫폼 호환성

- T5 JSON 계약/6개 통제와 program의 22개 요구를 합치거나 임의 치환하지 않는다.
- T10 `initial`/`post_apply`는 플랫폼 게이트의 평가 단계다. program의
  `preflight`/`postflight`와 일대일로 바꾸지 않는다. 특히 `post_apply`의 재대조는
  마이그레이션 실행 전 조건일 수 있다. 두 축과 실제 application ID를 따로 결속한다.
- 플랫폼 plan/context/report 해시는 원래 생산자의 계산 값을 소비한다. 같은 의미의 새
  계획 해시를 만들지 않는다. 서비스 context 지문은 별도 전송 계약의 식별자다.
- 플랫폼의 명시적 True/VerifiedAuthority 규칙과 패키지의 raise-on-deny None 규칙은
  혼용하지 않는다. 서비스의 새 인증/인가 경계는 기한이 있는 검증된 타입을 요구한다.
- 원격 head는 이번 구현 시작 시 위 SHA로 고정한다. 이후 delta는 기록·계약 시험 후 인수한다.

## 최근 기준에서 확인한 범위

- `94b7c33` 이후 T10 gate-record 호스트, T33 Security Hub, 등록 listener v2가 추가됐다.
- T7 자동 발급·회수 실측은 현재 자격 발급의 재사용 근거다. 서비스 audience는 별도 인수한다.
- T33 실측은 Security Hub 접근 거부/실패 보존이며 실제 양성 탐지 통합 성공이 아니다.
- T14 listener v2의 source NET-01.3은 실제 FAIL이다. 후보 method v2를 운영 v1
  프로필에 섞지 않는다. AWS/RKE2 전체 PASS 또는 운영 인수로 표현하지 않는다.

## 대안과 결과

패키지 직접 호출은 간단하지만 프로세스 격리를 시험할 수 없다. 모든 보안을 새 서비스로
이전하면 T19·T10 정본과 실행 책임이 중복된다. 제한된 판정 서비스를 선택하고 기존
제공자를 어댑터로 연결한다. 배포 계정/IAM/RBAC에서 실제 우회 차단은 별도 운영 시험이
필요하다. 로컬 TLS·프로세스 분리·DB 권한 시험을 클라우드 인수로 확대하지 않는다.

API/영속 저장 형식, 의존성 및 시험 결과는 구현과 함께 개발 기록에 추가한다.
